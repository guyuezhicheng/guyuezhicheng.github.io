只写检索到并逐条核对 arXiv 官方 abs 页的真实内容；预印本一律标注未经同行评审、待复现。今天两条都跟“编译链到底可不可信、编译器决定有多重要”正面相关。

3.1 CompCert4Lean：验证过的 C 编译器，六周被并行 agent 从 Rocq 搬到 Lean

  1. 出处：arXiv:2611.21084，v1 2026-11-16，cs.PL / cs.LO；Cong Wang、Zhiyang Chen、Fan Long、Martin Rinard。abs 页未逐作者印机构，不臆断（作者公开归属 MIT 等，但页面没逐条印，按规矩不写死）。预印本，未经同行评审、待复现；数据均为作者自报。
  2. 做了什么：把 CompCert 3.17 已验证编译器核心从 Rocq（Coq 的后继）整体移植到 Lean，由一位专家指挥并行 LLM agent、约六周完成。结果覆盖 typed CompCert C 到 x86-64 汇编， discharge 掉全部 4908 个证明义务、不引入项目专用公理，能产出可执行 Linux 二进制。1071 次人机交互里 88.8% 是工作流与协调，只有 3 次给技术方向。后续优化实验：同样 24 活跃小时预算下，GPT-6-astra 生成的 Lean 候选让目标程序运行时间比原版低 11.7%（Rocq 版 2.3%），且保住端到端正确性定理。
  3. 改变了哪个旧假设：推翻“把一个大规模形式化验证项目移植到另一种证明语言，必须领域专家逐行重写、无法交给自动化”。专家的角色从” supplying technical solutions“变成”组织工作流”， correctness 还能守住。
  4. 意义：形式化验证的编译器不再被一种证明语言锁死；迁移和维护成本大幅下降，专家可把精力放在编排而非手工证明。
  5. 关联今天：你今天写的 SQR(a+1) 一个括号错误，肉眼盯 -E 输出才能发现；CompCert 走另一个极端——用机器证明保证“源码到汇编的每一层变换都不改变语义”，这类错误在编译链里根本过不了证明。理解编译四步，才看得懂这类工作守的是哪一段；注意其性能数字与“六周”是作者自述，待独立复现。

3.2 Stratum：编译 lowering 和权重布局，让同一段 SNN 推理快 64 倍

  1. 出处：arXiv:2611.27277，v1 2026-11-20，cs.AR；Wajahat Riaz、Muhammad Adeel Pasha、Shahid Masud、Muhammad Ali Siddiqi。机构据来源报道为巴基斯坦拉合尔管理科学大学（LUMS），abs 页未逐作者印机构；该数字为周期级 gem5 模拟值、非真芯片实测。预印本，未经同行评审、待复现。
  2. 做了什么：把 snnTorch 训练的脉冲神经网络、基于 MLIR 的编译器栈、gem5 周期级 RISC-V 模型串成一个统一工作流，让性能开销能归因到具体的“编译器决策”和“硬件配置”。两个 SNN 专用编译器 pass：spike-gated lowering（跳过非活跃输入）和 spike-major 权重布局（连续内存访问）。在两层 N-MNIST 上：spike-gated lowering 把模拟推理时间从 453.2 ms 降到 7.04 ms（64×）；再叠加 spike-major 布局，4 MiB L2 下又降 37.2% 到 4.42 ms，L2 缩到 1 MiB 时加速从 1.59× 涨到 1.88×，预测类别不变。
  3. 改变了哪个旧假设：推翻“算法确定后性能就定了，编译器只是忠实翻译”。同样的网络、同样的预测结果，仅因 lowering 方式和权重在内存里怎么摆，就能差几十倍；而且收益随缓存大小变化，软硬件必须协同设计。
  4. 意义：编译器决策是一等性能杠杆，不是附属品；把训练、编译、周期级模拟打通后，芯片做出来之前就能定位瓶颈。
  5. 关联今天：今天学的宏和条件编译，是编译最前端、离源码最近的一层“编译器决定”——#define 怎么写直接改变编译器吃进去的文本。Stratum 在后端证明“代码怎么生成、数据怎么摆”能拉开 64×；你在这头先练好“文本怎么被替换”，两头的道理是同一个：别以为你写的代码就是机器跑的代码。

4. 新知讲解：预处理、宏、头文件守卫

4.1 编译四步与预处理的位置

  1. gcc hello.c -o hello 一步到位，中间其实走四步：预处理（cpp）→ 编译（cc1，源码变汇编）→ 汇编（as，汇编变目标文件 .o）→ 链接（ld，.o 加库变可执行）。
  2. 用 gcc -E hello.c -o hello.i 只做第一步，输出还是人能读的 C 文本，只是 #include 被粘贴进来、#define 被替换掉、#if 被裁剪掉、注释被删掉。
  3. 预处理是纯文本替换，不认识类型、不做语法检查。所以宏写错，编译器往往在展开之后才报错，报错位置还经常对不上你写的代码——这是宏难调的根源。

4.2 #define：对象宏与函数宏

  1. 对象宏：#define A 2，凡出现 A 就换成 2。
  2. 函数宏：#define SQR(x) ((x) * (x))，宏名后面紧跟括号才算函数宏；调用 SQR(3) 展开成 ((3) * (3))。
  3. 关键纪律：宏体里出现的每个参数都要单独括起来，整个表达式也要再括一层。少一层就出错，3.4 用实例说明。

4.3 -E 看展开：眼见为实

  1. 命令：gcc -E day15/min.c -o day15/min.i，打开 min.i 拉到最后，看 main 里那几行 printf 变成了什么。
  2. 你会看到 SQR_BAD(a+1) 那行变成 a+1*a+1，而 SQR(a+1) 那行变成 ((a+1)*(a+1))。差异就是括号。
  3. 不加 -o 时 gcc -E 直接打到终端，接 | tail -20 只看末尾，省得翻 stdio 头文件几千行。

4.4 SQR(a+1) 为什么错（本课核心）

  1. 陷阱定义：#define SQR_BAD(x) x * x。
  2. 代入 a+1 是文本替换，不是传参：SQR_BAD(a+1) → a+1 * a+1。乘法优先级高于加法，实际算的是 a + (1*a) + 1。取 a=3，结果是 3+3+1=7，而正确值应是 (3+1)²=16。
  3. 修正：#define SQR(x) ((x) * (x))。参数 x 各自带括号，整体再带括号，SQR(a+1) → ((a+1)*(a+1))=16。
  4. 对象宏同样有坑：#define B A + 3 时，B*2 展开成 A+3*2 = 2+6 = 8，不是 (2+3)*2=10。修正写法是 #define B (A + 3)。

4.5 多行宏与 do-while(0)

  1. 多行宏用 \ 续行，或直接写在一行。
  2. 带多条语句的宏要用 do { ... } while (0) 包起来。看 macro.c 里的 LOG_BRACE（花括号版）和 LOG_DO（do-while 版）：
    • if (x>0) LOG_BRACE("ok"); else printf("no\n"); 展开后 else 前面挂着一个多余的分号，else 找不到配对的 if，编译报错。
    • LOG_DO 展开成一个完整的 do-while 语句，末尾那个分号正好被 while(0); 吃掉，if/else 正常。
  3. 注意 LOG_BRACE 在 macro.c 里只是定义、没在 if/else 中调用，所以能编译；一旦按上面那样用就会炸——这是留给你的实验。

4.6 # 与 ##：字符串化和拼接

  1. #x 把参数变成字符串字面量：STR(hello) → "hello"。
  2. a##b 把两个记号粘成一个：CAT(v, 3) → v3。
  3. 直接写 #define CAT(a,b) a##b 时，CAT(v, VERSION) 会粘成 vVERSION（## 阻止参数展开）。要两层：#define CAT(a,b) CAT2(a,b) + #define CAT2(a,b) a##b，让 VERSION 先展开成 3，再粘成 v3，值为 33。这就是 macro.c 里的写法。

4.7 条件编译

  1. #ifdef DEBUG ... #else ... #endif：宏定义了走 if 分支。用 gcc -DDEBUG day15/macro.c 编译，输出会从 DEBUG off 变成 DEBUG on——不用改源码就能切换行为。
  2. #if defined(DEBUG)、#ifndef（没定义时为真）是同类写法；头文件守卫用的就是 #ifndef。

4.8 头文件守卫

  1. 一个头文件被间接 include 两次（a.h 包含 c.h，b.h 也包含 c.h，main 同时包含 a.h 和 b.h），里面的定义会被贴两遍，导致重定义错误。
  2. 标准写法：#ifndef GUARD_H / #define GUARD_H /（头文件正文）/ #endif。第一次进来 GUARD_H 未定义，进入并定义它；第二次进来已经定义，整段被跳过。见 day15/guard.h。
  3. macro.c 故意 #include "guard.h" 两次，靠守卫才不报错——把它当反面实验的起点：删掉守卫三行再编译，看重定义报错。
  4. #pragma once 是更短的写法，多数编译器支持；但可移植性和可判定性不如 include guard，作业和面试写标准守卫。

4.9 最小可运行示例（已落盘 day15/min.c，输出逐字可复现）

/* min.c - D15 minimal macro demo: object/function macros, trap vs fixed. */
#include <stdio.h>

#define A 2
#define B A + 3              /* trap: object-like macro, no parens */
#define SQR_BAD(x) x * x     /* trap: arg not parenthesized */
#define SQR(x) ((x) * (x))   /* fixed: parens on arg AND whole expression */

int main(void) {
    int a = 3;
    printf("SQR_BAD(a)   = %d\n", SQR_BAD(a));
    printf("SQR_BAD(a+1) = %d\n", SQR_BAD(a+1));
    printf("SQR(a+1)     = %d\n", SQR(a+1));
    printf("B            = %d\n", B);
    printf("B*2          = %d\n", B * 2);
    return 0;
}

编译运行（Windows / Linux 通用）：

gcc -std=c11 -Wall -Wextra day15/min.c -o day15/min && day15/min

期望输出（已用等价 Python 复刻算准）：

SQR_BAD(a)   = 9
SQR_BAD(a+1) = 7
SQR(a+1)     = 16
B            = 5
B*2          = 8

SQR_BAD(a+1)=7 就是陷阱现场，SQR(a+1)=16 是修正结果；B*2=8 提醒你对象宏也要括整体。
