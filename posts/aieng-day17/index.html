3. 学术雷达（第 17 期 · 2026-11-26 检索）

3.1 KuroANN：按 match count 决定每个查询读几次 SSD，不再一刀切

  1. 出处：arXiv:2611.32908，v1 2026-11-24，cs.OS / cs.DB；Soobin Cho、Nakyung Lee、Jiwoong Park、Gyuyeong Kim。abs 页未逐作者印机构，不臆断。预印本，未经同行评审、待复现；性能为作者在论文中报告的结果。
  2. 做了什么：面向分区索引的 SSD 上过滤式向量检索系统。已有方案对同一 selectivity 区间内的所有查询分配相同的 SSD 读次数，很多查询白读。KuroANN 的观察是：每个查询的“匹配数”（能通过过滤条件的向量个数）在检索前就知道，而需要读多少次 SSD 取决于这个匹配数。做法：离线测好每个匹配数下达到目标召回要探测多少分区、读多少候选；运行时按匹配数查表，只过滤被探测的分区，当后续读取不太可能再帮上忙时就停。论文报告相较 PipeANN-Filter 和 Faiss 吞吐最高提升 34.5× 和 9.10×。
  3. 改变了哪个旧假设：推翻“同一过滤强度下所有查询该读同样多数据”。查询之间的匹配数差异是可用信息，用它做逐查询的 I/O 预算分配，能砍掉大量无用读取。
  4. 意义：高召回过滤检索的瓶颈在 SSD 读，按需分配 I/O 比统一策略更省；把“读多少”从常量变成按查询特征决策的变量。
  5. 关联今天：你今天写的 fread/fgets 默认是把文件从头读到尾或按固定块读——这正是 KuroANN 批评的“一刀切”。它给的启发是：读文件的预算应该由“这次到底要多少有效数据”决定，先估再读、够了就停，而不是无脑把整个文件灌进内存。理解“每次 I/O 都有成本、按需读”，才算真正进了文件 I/O 的门。作者自报的性能数据待独立复现。

3.2 LiZoneDedup：把 ZNS SSD 的 append-only 变成去重的前提，砍掉全局指纹索引

  1. 出处：arXiv:2611.29273，v1 2026-11-22，cs.DC；Hao Fan、Xianwei Lv、Ruikun Luo。abs 页未逐作者印机构，不臆断。预印本，未经同行评审、待复现；数据为作者在 1 TB ZNS SSD 上的实测自报。
  2. 做了什么：数据去重能减少写放大、延长闪存寿命，但新兴的 Zoned Namespace（ZNS）SSD 上一直没人做存储内去重——传统方案依赖页级 FTL 重映射重复写、依赖远超控制器 DRAM 的全设备指纹索引，这两样 ZNS 都没有。LiZoneDedup 的洞察是：ZNS 的 append-only 契约天然适合去重——重复映射一旦记录就不再原地改写，于是去重元数据从“可变页级表”变成“追加日志”，指纹从“全局索引”变成“每 zone 的小索引”。三个机制：设备侧选定的写原语（对主机隐藏 zone 放置）、基于内容的路由（把每次查找限制在一小组候选 zone）、按生命周期分离的元数据（每 zone 身份索引 + 追加式引用计数）。论文报告在 1 TB ZNS SSD 上把约 10.7 GB 的全局指纹索引换成每 zone 几百 KB、封区后落到 NAND 的索引，控制器 DRAM 恒定在 37–50 MB，逻辑写吞吐提升 1.1–3.5×，物理写最多减少 85%。
  3. 改变了哪个旧假设：推翻“存储内去重必须要有页级 FTL 和全局指纹索引”。换一个前提（append-only），元数据的形态整个变了——可变表变日志、全局索引变分区索引，重资源需求随之消失。
  4. 意义：去重这种“写路径上的数据处理”可以下沉到设备里，且不用为 ZNS 重新引入它刻意去掉的 FTL；对容器镜像、快照、备份这类版本化负载尤其有价值。
  5. 关联今天：你今天用 "w"/"wb" 写文件，默认假设是“写哪里、覆盖什么”由操作系统管，写模式只是个标志位。LiZoneDedup 说明：写入契约（能不能原地改）直接决定了元数据怎么设计、会不会撑爆内存。今天记住——文件模式不是无关紧要的字符串，w 会截断、a 会追加，不同的写契约对应完全不同的底层代价。作者自报的性能数据待独立复现。

4. 新知讲解：文件 I/O、文本/二进制、errno

4.1 文件是什么：从 C 的角度看

  1. 文件就是磁盘上的一串字节，C 不管它里面装的是文字还是图片——在你调用读写函数之前，它全是字节。FILE * 是标准库给你的一层抽象（缓冲 + 文件位置 + 状态标志），屏蔽了系统调用的差异；真正干活的是 fopen 返回的那个句柄。
  2. 三种常用打开模式："r" 只读、"w" 只写且先把文件截断成 0（存在就清空）、"a" 追加（写永远加到末尾）。加 b 变成 "rb"/"wb"/"ab" 就是二进制模式，加 + 变成读写两用（如 "r+"）。模式串写错是新手最常见的坑——"w" 一开就把原文件清了。
  3. 程序结束前必须 fclose(fp)：它把缓冲区里没写完的数据刷到磁盘（flush），并归还系统资源。忘了关，轻则数据没落盘，重则文件描述符耗尽。

4.2 文本模式 vs 二进制模式（今天第一个核心考点）

  1. 差别只有一条：文本模式会对换行符做翻译。Windows 上文本模式写 \n 会自动变成 \r\n（两个字节），读的时候再把 \r\n 还原成 \n；二进制模式一个字节都不动，写什么就是什么。Linux/macOS 上两者基本没差别（换行就是 \n）。
  2. 直接证据：fputs("a\nb\n", fp) 写了 4 个字符。"wb" 模式文件永远是 4 字节；"w" 模式在 Windows 上是 6 字节（多了两个 \r）。讲义配套 day17/io.c 的 text 模式会实测这两个数字打印出来。
  3. 什么时候必须用二进制：结构体、图片、压缩数据、模型权重——任何“字节值本身就是数据”的场景。拿文本模式去写二进制，0x0A（换行）会被插入 \r、0x1A（EOF 字符）可能被截断，文件直接损坏。反过来，纯文字用文本模式更省事（跨平台换行自动适配）。
  4. 判断标准一句话：这个文件要不要人直接看懂？要 → 文本；不要 → 二进制。

4.3 读写函数与它们的返回约定（今天第二个核心考点）

  1. fgets(buf, size, fp)：读一行（最多 size-1 个字符），成功返回 buf，读到文件末尾或出错返回 NULL。用 while (fgets(...) != NULL) 循环，别用 while (!feof(fp))——后者会多跑一次、拿上一次的旧 buf 再处理一遍，配套 day17/traps.c 有实测证据。
  2. fwrite(ptr, size, n, fp) / fread(ptr, size, n, fp)：第二个参数是“每个元素的字节数”，第三个是“要几个”。返回值是成功读写的元素个数，不是字节数，所以可能短写（返回 < n）。正确写法是 size_t got = fwrite(...); if (got != n) { /* 处理短写 */ }。算字节数要乘回去：got * size。
  3. printf/fprintf/fputs 用于文本，fwrite/fread 用于二进制块。别混：用 fprintf("%s", binary_data) 写二进制，遇到 \0 就停了。
  4. fseek(fp, offset, whence) 移动文件位置，whence 常用 SEEK_SET（开头）、SEEK_END（末尾）、SEEK_CUR（当前）；ftell(fp) 返回当前位置（字节数）。两者配合能测文件大小：fseek(fp, 0, SEEK_END); long n = ftell(fp);。注意 ftell 返回 long，超大文件要用 64 位版本。
  5. 二进制块拷贝的标准循环：while ((n = fread(buf, 1, sizeof buf, in)) > 0) fwrite(buf, 1, n, out);——用 1 作元素大小，返回值直接是字节数，最不容易算错。day17/io.c 的 copy 模式就是这个写法。

4.4 errno 与“打开失败不崩”（今天第三个核心考点）

  1. errno 是标准库维护的一个全局 int，记录最近一次失败的错误码。fopen 失败时返回 NULL 并设置 errno。常见值：ENOENT（2，文件/路径不存在）、EACCES（13，权限不足）——编号 POSIX 平台基本一致，Windows CRT 也沿用 2/13 这套。
  2. 把它变成人话：strerror(errno) 返回可读字符串，如 "No such file or directory"。不同系统/语言环境下文字略有差别，所以检验只要求“可读、能看懂”，不要求逐字一样。
  3. 三条纪律：
    • 用前清零：errno = 0;，因为它是上次失败留下的值，不清零你分不清是不是本次的错误。
    • 失败后立刻存：if (fp == NULL) { int e = errno; ... }，中间别调用别的库函数，可能被改写。
    • 只在失败时看它：函数成功了，errno 里可能是残留的旧值，不能拿来当“出错了”的证据。
  4. 打开不存在文件的正确姿势（今天检验的标准答案）：
errno = 0;
fp = fopen("no_such.txt", "r");
if (fp == NULL) {
    printf("fopen failed: errno=%d, %s\n", errno, strerror(errno));
    return 1;   /* 或走降级逻辑，绝不能继续用 fp */
}
  1. 不检查的后果：fp 是 NULL，后面任何 fgets/fwrite 都是对空指针解引用 → 段错误（Segmentation fault），进程直接崩。这就是“打开失败不崩”这条检验要挡的事故。

4.5 最小示例代码（day17/min.c，完整可直接编译）

一份文件把文本写/读、二进制写/读、打开失败处理全跑一遍，末尾自动清理测试文件：

/* day17/min.c - 最小示例：文本读写 + 二进制读写 + 打开失败不崩
 * 编译: gcc -std=c11 -Wall -Wextra day17/min.c -o day17/min
 * 运行: ./day17/min   (Windows: day17\min.exe)
 */
#include <stdio.h>
#include <string.h>
#include <errno.h>

typedef struct {
    int id;
    double score;
} Rec;

int main(void)
{
    const char *txt = "day17_note.txt";
    const char *bin = "day17_data.bin";
    char buf[128];
    FILE *fp;
    Rec r = {7, 93.5}, back;
    size_t n;

    /* 1. 写文本文件 */
    fp = fopen(txt, "w");
    if (fp == NULL) {
        printf("open %s for write failed: %s\n", txt, strerror(errno));
        return 1;
    }
    fprintf(fp, "hello io\nline2\n");
    fclose(fp);

    /* 2. 读文本文件 */
    fp = fopen(txt, "r");
    if (fp == NULL) {
        printf("open %s for read failed: %s\n", txt, strerror(errno));
        return 1;
    }
    while (fgets(buf, sizeof buf, fp) != NULL) {
        printf("TXT: %s", buf);
    }
    fclose(fp);

    /* 3. 写二进制文件 */
    fp = fopen(bin, "wb");
    if (fp == NULL) {
        printf("open %s for write failed: %s\n", bin, strerror(errno));
        return 1;
    }
    n = fwrite(&r, sizeof r, 1, fp);
    printf("BIN write: %zu item(s)\n", n);
    fclose(fp);

    /* 4. 读二进制文件 */
    fp = fopen(bin, "rb");
    if (fp == NULL) {
        printf("open %s for read failed: %s\n", bin, strerror(errno));
        return 1;
    }
    n = fread(&back, sizeof back, 1, fp);
    printf("BIN read: %zu item(s), id=%d score=%.1f\n", n, back.id, back.score);
    fclose(fp);

    /* 5. 打开不存在的文件：不崩，打印可读错误 */
    errno = 0;
    fp = fopen("day17_no_such_file.txt", "r");
    if (fp == NULL) {
        printf("expected failure: errno=%d, %s\n", errno, strerror(errno));
    } else {
        printf("unexpected success\n");
        fclose(fp);
    }

    remove(txt);
    remove(bin);
    return 0;
}

编译运行：gcc -std=c11 -Wall -Wextra day17/min.c -o day17/min && day17/min

期望输出（6 行；最后一行 errno 编号在 POSIX/Windows CRT 均为 2，strerror 文字因系统而异）：

TXT: hello io
TXT: line2
BIN write: 1 item(s)
BIN read: 1 item(s), id=7 score=93.5
expected failure: errno=2, No such file or directory

关键点：fgets 把 \n 也读进了 buf，所以 printf("TXT: %s", buf) 不用自己补换行；二进制写结构体是直接把内存里的字节倒出去，同一程序同平台读回来必然一致，但换个编译器/架构/字节序就不一定能读——二进制文件不跨环境通用。

  2. day17/io missing 打开不存在文件时程序不崩、退出码正常，并打印出 errno 编号与一句人能读懂的错误（如 errno=2, No such file or directory，文字因系统而异可接受）。崩了、静默失败、或只打印编号没给人话 = 不过。
  3. 不看资料说清文本 vs 二进制的差别：\n 在 Windows 文本模式会变 \r\n，二进制模式字节原样；并能在自己机器上用 io text 的实测字节数佐证。说反或拿不出实测数字 = 不过。
  4. 说清 errno 三条纪律（用前清零、失败立刻存、只在失败时看），并解释为什么 while (!feof(fp)) 会多处理一次（配合 traps 输出）。少一条或说不出 feof 多跑的原因 = 不过。
  5. day17/io_notes.md、day17/errno_table.md 存在且含实际输出片段，git log -1 看得到当日 commit；第 5 节第 8 项补档清单逐项有产出或明确缺口记录。缺一项 = 不过。
