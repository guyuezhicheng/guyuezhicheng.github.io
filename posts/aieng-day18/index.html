3. 学术雷达（第 18 期 · 2026-11-27 检索）

3.1 A CPU Inside an LLM：把精确算术电路零梯度编译进预训练权重

  1. 出处：arXiv:2611.26450，v1 2026-11-19，cs.AI；单作者 Tanmay Sah。abs 页未印机构，不臆断。预印本，未经同行评审、待复现；性能为作者在论文中报告的结果。
  2. 做了什么：不用梯度微调、不用运行时外挂工具，用闭式的“电路移植”手段把确定性计算直接编译进预训练 LM 的权重，且限制每层归一化漂移、保住自然语言能力。三个机制：两层 Mellin-GLU 积分把未知的逐 token RMSNorm 缩放变成对数间隔门网格上的平移（>250× 动态范围，带 IEEE 754 误差界）、跨 token 的尺度抵消、轴向扩维加范数补偿。一个 5 阶段编译器能合成 4–8 位有符号 {+,-,×} 电路（常数 TC0 深度）、3-literal 布尔电路（100%，N=1728）和 5-bit Majority/Parity 电路（100%）。在 6 位算术上（N=1200，BF16），Granite 4.2 3B 与 Qwen 3.5 4B 分别达到 99.17% / 100.00% 的 ALU-prefix 准确率。
  3. 改变了哪个旧假设：推翻“精确多位数算术必须靠微调或外部工具解释器”。作者把算术当作可以编译的确定性电路、直接写进权重，连布尔门和 Majority/Parity 都能精确落地——精度不再只能靠训练“学”出来。
  4. 意义：给“LLM 做算术不可靠”提供了一个不训练、不外挂的补法；同时把 IEEE 754 误差界、位宽扩展这类底层数值问题推到台前——想让模型算对，最后还是要回到补码、进位、精度边界这些今天学的东西。
  5. 关联今天：论文的核心难点是精度边界——BF16 下进位链会丢精度（作者用 FP32 sidecar 才把 6 位算术做到 100%），5-bit 电路、4–8 位有符号电路、IEEE 754 误差界，全是在跟“有限位宽能表示什么”较劲。你今天学的补码（负数怎么表示）、溢出（超出位宽会怎样）、掩码（怎么抠出某几位），就是这套电路的原材料。后面 D142 把模型从 fp32 压到 int8，本质也是有限位宽的取舍。作者自报数据待独立复现。

3.2 The Vulnerability Window：4-bit 量化几乎不动基准分，却悄悄改写偏好判断

  1. 出处：arXiv:2611.27155，v1 2026-11-20，cs.LG / cs.CL；Omkar Shewale、Deepak Kumar、Divakar Kumar Yadav。abs 页未逐作者印机构，不臆断。预印本，未经同行评审、待复现；数据为作者在论文中的实测报告。
  2. 做了什么：奖励模型和 LLM 评判器常被压到 4 bit 以便低成本给大量候选打分，常规检查是“基准准确率几乎没变”。作者测了 8 个奖励模型（0.6B–8B）、3 个生成式评判器、4 种 4-bit 量化器，发现：量化在 RewardBench 上改写了 1.1%–12.3% 的成对偏好判断，而聚合准确率最少只动 0.03 分（p=1.00）——因为量化修正的错误和引入的错误互相抵消了。翻转集中在“全精度决策间距 m 相对量化噪声尺度 σ 较小”的位置（高斯近似 Φ(-|m|/σ) 描述聚合翻转率，在 30 个标量设定上都偏高预测、对生成式评判器失效）。后果：best-of-64 里 14.6%–65.7% 的问题选出了不同候选，而最终答案只变 2.6%–9.6%。
  3. 改变了哪个旧假设：推翻“基准分不变 = 量化安全”。聚合准确率是个会自我抵消的指标，低位宽量化在边界附近的系统性翻转被它掩盖了——“看起来没变”不等于“没变”。
  4. 意义：做 RLHF 或 LLM-as-judge 时，选量化方案不能只看 RewardBench 总分，要看决策间距（margin）与实测翻转率。位宽压低不是无损压缩，它改变了数值在边界上的行为，而边界正是决策最敏感的地方。
  5. 关联今天：4 bit 只有 16 个可表示的值，把连续的分数塞进这 16 个格子，边界附近的数就会被“压缩”到同一个值——这就是你今天学的有限位宽表示和截断/舍入的真实后果。今天理解“溢出不报错但结果错了”“低位宽会吞掉精度”，明天看到 int8 量化掉点就不会奇怪。这也解释了课表为什么在 D18 检验里专门写“为后面量化埋线”。作者数据待独立复现。

4. 新知讲解：位运算、大小端、补码、整数溢出

4.1 六个位运算符（今天第一个核心考点）

  1. C 直接操作二进制位的六个运算符：&（按位与）、|（按位或）、^（按位异或）、~（按位取反，一元）、<<（左移）、>>（右移）。只对整型（char/short/int/long 及其 unsigned 版）有效，浮点数用不了。
  2. 逐个说清：
    • a & b：两位都是 1 才得 1 → 用来取出/保留某些位（掩码）。
    • a | b：有一位是 1 就得 1 → 用来置位（把某位设成 1）。
    • a ^ b：两位不同才得 1 → 用来翻转某位（和 1 异或），或判断差异。
    • ~a：逐位取反，~0xF0（8 位看）是 0x0F。
    • a << n：左移 n 位，右边补 0，等价于乘 2^n（不溢出时）。
    • a >> n：右移 n 位。正数左边补 0；负数右移是实现定义（多数编译器算术右移、左边补符号位），写跨平台代码别依赖它。
  3. 掩码（mask）四件套，假设想操作第 k 位，掩码就是 1u << k：
    • 测位：(x & (1u << k)) != 0
    • 置位：x |= (1u << k)
    • 清位：x &= ~(1u << k)
    • 翻转：x ^= (1u << k)
  4. 坑：& 的优先级低于 ==，x & 1 == 0 会被解析成 x & (1 == 0) = x & 0，永远为 0。测位必须写 (x & 1) == 0。同理 < > 也高于移位之外的位运算，拿不准就加括号。配套 day18/traps.c 坑 3 有实测。

4.2 大小端（今天第二个核心考点，检验要求手写）

  1. 一个多字节整数在内存里“低位字节放低地址还是高地址”，有两种排法：
    • 小端（little endian）：低位字节放低地址。x86 / x86-64 / 多数 ARM 默认小端。
    • 大端（big endian）：高位字节放低地址。网络字节序（TCP/IP）是大端，早期 POWER/SPARC 是大端。
  2. 例子：unsigned int x = 0x11223344;（小端机器，地址从低到高）内存是 44 33 22 11——最低有效字节 0x44 在最前面。大端则是 11 22 33 44。
  3. 手写判断方法 A（指针法）：让 x = 1（字节是 01 00 00 00），看第一个字节：是 1 → 小端，是 0 → 大端。
int endian_by_ptr(void)
{
    unsigned int x = 1u;
    return *(unsigned char *)&x == 1;
}
  1. 手写判断方法 B（union 法）：同一块内存按 int 写、按 unsigned char 数组读，看 c[0]。
int endian_by_union(void)
{
    union { unsigned int i; unsigned char c[sizeof(unsigned int)]; } u;
    u.i = 1u;
    return u.c[0] == 1;
}
  1. 为什么用 unsigned char * 去读：char 是“1 字节”的最小寻址单位，用它访问能绕开类型解释、看到原始字节。用 int * 读就没意义了。
  2. 什么时候大小端才是问题：同一台机器内部不用管，CPU 怎么存怎么取自洽。只有跨机器传字节（网络协议、二进制文件格式、fwrite 一个结构体到磁盘再换台机器读）时才要统一字节序。D17 讲过“二进制文件不跨环境通用”，大小端就是原因之一。

4.3 补码：负数怎么表示（今天第三个核心考点）

  1. C 里有符号整数用补码（C23 起强制，此前主流实现都是）。正数补码就是它本身；负数 -x 的补码 = 把 x 的位全部取反再加 1，即 ~x + 1。
  2. -1 为什么是全 1：按公式，1 的位（…0001）取反得 …1110，加 1 得 …1111。所以 8 位看 -1 是 0xFF，32 位是 0xFFFFFFFF。配套 min.c 里 printf("%u", (unsigned)-1) 会打印 4294967295，就是这个道理。
  3. 补码的妙处：加法和减法用同一套电路。a - b 就是 a + (~b + 1)，硬件不用为减法单独造一套逻辑。这也是 2.1 那篇论文能把加减乘编成统一电路的原因。
  4. 为什么范围不对称：int 32 位，补码范围是 -2^31 ~ 2^31-1，即 INT_MIN = -2147483648、INT_MAX = 2147483647 打住——负数多一个。因为 0 占了正数那边的编码，负数那边多出来的 0x80000000 就表示 -2^31。所以 -INT_MIN 会溢出（正数表示不了 2147483648）。
  5. 无符号 vs 有符号：同一个位模式 0xFFFFFFFF，当 unsigned 看是 4294967295，当 int 看是 -1。位是一样的，解释方式不同。%u 和 %d 打印同一个值结果不同，就是这个原因。

4.4 整数溢出：为什么不报错（今天第四个核心考点，为量化埋线）

  1. 无符号溢出是定义良好的回绕（wrap-around）：按 2^N 取模。32 位无符号数 UINT_MAX + 1 = 0，0u - 1u = UINT_MAX。这是 C 标准明确保证的，不报错、结果可预测。min.c 最后一行打印 UINT_MAX+1=0。
  2. 有符号溢出是未定义行为（UB）：一旦发生，编译器想怎样都行——可以回绕、可以崩溃、可以做“它永远不会发生”的优化。所以编译器通常不报错，甚至会据此优化掉你的检查：写一个 if (x + 1 > x) 想检测溢出，编译器可能直接判定它恒真（因为假定不溢出）而删掉。traps.c 坑 5 用 volatile 防止这个优化，让你看到回绕值。
  3. “为什么不报错”的完整回答：
    • 硬件层面：加法就是按位加，进位自然丢掉（mod 2^N），硬件没义务报。
    • 标准层面：有符号交给“未定义”，给编译器优化自由；无符号定义成回绕，所以也不算错。
    • 检测层面：想查有符号溢出得主动用 UBSan（gcc -fsanitize=undefined）或手写边界检查，默认编译不会告诉你。
  4. 和量化的连接（埋线）：量化就是把高精度数压到低位宽——fp32 → int8 只有 8 位，范围 -128~127。超出范围的数会被饱和（clamp）到边界或回绕到另一头，边界附近的数会被舍到同一个格子里。2.2 那篇论文里 4-bit 量化改写偏好判断，本质就是有限位宽 + 边界舍入。今天把“位宽有限 → 表示有限 → 溢出/舍入不可避免”这根链条搞通，D142 的量化掉点分析才有抓手。

4.5 最小示例代码（day18/min.c，完整可直接编译）

一份文件把大小端、补码、位集合、无符号回绕全跑一遍：

/* day18/min.c - 最小示例：大小端 + 补码 + 位运算集合 + 无符号回绕
 * 编译: gcc -std=c11 -Wall -Wextra day18/min.c -o day18/min
 * 运行: ./day18/min   (Windows: day18\min.exe)
 */
#include <stdio.h>
#include <limits.h>

/* 方法1：指针法。看 int 1 的最低位字节是 1(小端) 还是 0(大端) */
int endian_by_ptr(void)
{
    unsigned int x = 1u;
    return *(unsigned char *)&x == 1u;
}

/* 方法2：union 法。同一块内存按 int 写、按 unsigned char 读 */
int endian_by_union(void)
{
    union { unsigned int i; unsigned char c[sizeof(unsigned int)]; } u;
    u.i = 1u;
    return u.c[0] == 1u;
}

int main(void)
{
    unsigned int set = 0u;

    /* 1. 大小端 */
    printf("endian(ptr)=%s endian(union)=%s\n",
           endian_by_ptr() ? "little" : "big",
           endian_by_union() ? "little" : "big");

    /* 2. 补码：-1 的全部位都是 1；~x + 1 == -x */
    printf("-1 as unsigned = %u (0x%08X)\n", (unsigned)-1, (unsigned)-1);
    printf("~5 + 1 = %u, -5 as unsigned = %u\n", ~5u + 1u, (unsigned)-5);

    /* 3. 位运算集合：位 k 为 1 表示元素 k 在集合中 */
    set |= (1u << 3) | (1u << 5);
    printf("set=0x%02X has3=%u has4=%u\n", set,
           !!(set & (1u << 3)), !!(set & (1u << 4)));
    set &= ~(1u << 3);
    set ^= (1u << 6);
    printf("set=0x%02X has3=%u has6=%u\n", set,
           !!(set & (1u << 3)), !!(set & (1u << 6)));

    /* 4. 无符号回绕：定义良好，按 2^32 取模 */
    printf("UINT_MAX=%u UINT_MAX+1=%u\n", UINT_MAX, UINT_MAX + 1u);
    return 0;
}

编译运行：gcc -std=c11 -Wall -Wextra day18/min.c -o day18/min && day18/min

期望输出（5 行；本机 x86-64 小端）：

endian(ptr)=little endian(union)=little
-1 as unsigned = 4294967295 (0xFFFFFFFF)
~5 + 1 = 4294967291, -5 as unsigned = 4294967291
set=0x28 has3=1 has4=0
set=0x60 has3=0 has6=1
UINT_MAX=4294967295 UINT_MAX+1=0

逐行解读：-1 按无符号打印是全 1；~5 + 1 等于 -5（补码公式）；集合先置入 3、5 得 0x28，清掉 3、翻转 6 得 0x60；无符号加 1 回绕成 0。注意 printf 里 !! 是把“非 0”规整成 0/1，方便看。

  2. 大小端四模式：gcc -std=c11 -Wall -Wextra day18/bits.c -o day18/bits && day18/bits endian，看两种判断法结果一致、逐字节是 44 33 22 11（小端）。把 0x11223344 改成 0x01020304 再看一遍，确认逐字节输出跟着变。
  3. 位运算与集合：day18/bits bits 看六个运算符结果，a&b=30 a|b=FC a^b=CC ~a=FFFFFF0F；day18/bits set 看集合增删查；再自己写 5 行代码：用掩码取出 0xABCD 的高 8 位（应为 0xAB）。
  4. 溢出与五个坑：day18/bits overflow 看回绕和补码边界；gcc -std=c11 -Wall -Wextra day18/traps.c -o day18/traps && day18/traps 看 5 个坑，重点看坑 3（(1&2)==0 vs 1&2==0 结果相反）和坑 5（有符号溢出回绕成 INT_MIN，说明这不是你能依赖的行为）。加 -fsanitize=undefined 重编译 traps，观察 UBSan 报不报坑 5。

6. 产出清单（必须落盘）

  1. day18/min.c — 最小示例（已落盘，讲义 3.5 代码块与它逐字一致）。
  2. day18/bits.c — 完整版（已落盘），含 endian / bits / set / overflow 四个模式。
  3. day18/traps.c — 五个坑的可运行演示（已落盘）。

  5. day18/twos_complement.md — 手推记录：8 位下 -1、-5、-128 的补码，~x + 1 == -x 验证，INT_MIN/INT_MAX 各是多少、为什么不对称。

7. 检验标准（5 条硬条件，逐条能回答“过没过”）

  1. day18/min.c 编译零 error，./day18/min 输出 6 行与 3.5 完全一致（大小端、两个补码行、两个集合行、回绕行）。少一行或对不上 = 不过。
  2. 不看资料手写判断大小端的 C 代码（指针法或 union 法任选其一），编译运行得出与 bits endian 一致的结果，并能说清为什么 unsigned char* 能看到原始字节、为什么 x=1 时首字节是 1 就是小端。写不出或解释不清 = 不过。
  3. 说清补码三件事：-1 为什么全 1、~x+1 == -x、int 范围为何 -2^31 ~ 2^31-1（负数多一个）；并能在 8 位纸上写出 -5 的补码 0xFB。错一件 = 不过。
  4. 回答“溢出为何不报错”：无符号溢出是定义良好的回绕（mod 2^N，举例 UINT_MAX+1=0）、有符号溢出是 UB（编译器可假定不发生、可能优化掉你的检查，默认不报，要查得靠 UBSan/手写边界检查），并说清这条怎么连到后面的量化（低位宽 → 范围有限 → 饱和/回绕/舍入）。少一层或说不出量化连接 = 不过。
  5. day18/endian_notes.md、day18/twos_complement.md 存在且含实测输出与手推过程，git log -1 看得到当日 commit；第 5 节第 8 项补档清单逐项有产出或明确缺口记录。缺一项 = 不过。
