2. 学术雷达 · 第 8 期（2026-11-17 检索）

今天两条都撞在「指针与内存边界」上：一条让编译器用 SMT 求解器证明内存安全检查是死代码、直接删掉；一条靠读显存里的字节做 LLM 推理取证。都已逐条核对 arXiv 官方 abs 页原文。

2.1 ODeSSy：用 SMT 证明「这个越界检查永远不会被触发」，然后把检查删掉

  • 出处：arXiv:2611.17737《Super-Analysis for Aggressive yet Scalable Compiler Optimization》，v1 2026-11-13 04:36 UTC，cs.PL / cs.SC；作者 Amirali Ebrahimzadeh、Amir Shaikhha；abs 页未逐作者印机构（作者单位以论文 PDF 为准，讲义不臆断）；https://arxiv.org/abs/2611.17737 。
  • 做了什么：提出 solver-based super-analysis——用昂贵的 SMT 求解器做分析，但代码变换仍是常规的，不做程序合成。落地成 LLVM pass 叫 ODeSSy，专门证明 sanitizer trap 和原生语言的安全检查（边界检查之类）不可达，然后移除。关键论点是：要证明一个检查是死的，常常需要同时用上 LLVM 三个独立分析的事实，这是个「合取蕴含」问题，适合交给 SMT 求解器，而不是任何单一数据流分析。同一套机制服务 4 种前端语言：Julia 的 GEMM 快 3.78×，Swift 的 Base64 编码器经 guard synthesis 快 1.44×，Julia 的 LZ77 压缩快 4.01×。对比 LLVM 的 superoptimizer Souper，ODeSSy 删掉更多检查且耗时显著更短，能当在线编译 pass 用。
  • 改变了哪个旧假设：激进优化只有两个极端——传统优化毫秒级但靠临时启发式、漏机会；超优化器能合成更快代码但要跑几小时、只能离线跑小 kernel。它证明「贵分析 + 常规变换」这条中间路线可行：不合成代码，只把安全性证明交给求解器，就能在线删检查。
  • 意义：把「运行时安全检查」和「编译期能否证明它多余」连成一条线。你写的每个越界判断、每个 sanitizer trap，理论上都存在「被证明不可达而删除」的可能；这一刀砍在哪，取决于编译器对地址关系的推理能力。
  • 关联今天：D8 讲的是地址运算——p+1 到底跳几字节、a+n 这个地址合不合法。ODeSSy 删的正是这类「访问会不会越界」的检查，它得先把指针/地址关系推理清楚才敢删。今天你手算 &a[i+1]-&a[i]，就是在做编译器证明安全检查时做的同一类算术。D11 还会用 AddressSanitizer 主动插检查抓越界，跟这篇正好是一正一反：一边插，一边证明确实多余再删。
  • 状态：arXiv 预印本，未经同行评审、待复现；加速比均为作者自测，暂无独立复现。

2.2 From Bytes to Behavior：不改一行代码，从活着的 GPU 进程里按地址读回字节当证据

  • 出处：arXiv:2611.18272《From Bytes to Behavior: Request-Level Attribution from Live GPU Hidden States》，v1 2026-11-13 15:04 UTC，cs.CR / cs.AI；作者 Jonathan Pan、Yidi Yuan、Xin Wei Chia、Xinhui Su、Vincent Tan、Brenda Ong；abs 页未印机构（第三方报道指向新加坡 Home Team Science and Technology Agency，此处仅按 abs 页原文，不把机构写死）；https://arxiv.org/abs/2611.18272 。
  • 做了什么：以往 ML 系统的内存取证只看静态产物（权重、prompt 日志），看不到正在运行的推理进程的瞬时计算状态。这篇用一个「非修改型」调试器，从活 GPU 进程里读出每层的 residual-stream 激活，不需要事先知道模型结构参数或权重。方法是六阶段流程 + 平台适配器：用 PyTorch 分配器时钟或 kernel-launch 时钟定位显存里的 tensor 分配，再读出来。在 9 类架构的 33 个开源 decoder-only 模型上验证，恢复的字节 byte-exact；下游用线性探针在留出 prompt 上区分「拒绝 / 遵从」，AUROC 0.88。
  • 改变了哪个旧假设：分析一个不能重启、不能改动的生产 LLM 服务，只能靠磁盘上的静态产物或应用层日志。它证明「对活进程做只读的观察式访问、拿到字节级中间状态」是可行的，而且不碰权重、不改内存、不插 hook。
  • 意义：地址本身就是一种能力——知道某块 tensor 分配在显存的哪个位置、什么时候被分配，就能把原始字节读出来当证据。这给「指针是内存地址」上了一堂极端实例课：所有对内存内容的读取，本质都是「拿到地址 + 读那段字节」。
  • 关联今天：今天写的 int *p = &x，p 里装的就是一个地址，*p 就是「顺着这个地址读字节，再按 int 解释」。这篇论文是同一件事的豪华版——把 p 换成显存里 tensor 的地址，把 *p 换成调试器读显存，把 int 解释换成线性探针解释。它还能反衬 D8 的边界：读得对不对，取决于你有没有找对地址和类型；找错一个字节，解释出来的就是垃圾。
  • 状态：arXiv 预印本，未经同行评审、待复现；byte-exact 与 AUROC 0.88 为作者在受控实验室条件下自测，论文自述在 vLLM 上约 2% 偏差，真实生产环境未验证。

3. 新知讲解

3.1 指针就是「装地址的变量」

  1. int x = 42; int *p = &x; — x 是一个 int 格子，p 是另一个格子，里面装的是 x 那个格子的起始地址。类型 int * 读成「指向 int 的指针」，说的是 p 里那个地址处该按 int 来解释。
  2. &x 取地址，*p 解引用。*p 不是「p 乘 something」，是「到 p 存的地址去，把那块内存当 *p 的类型读写」。
  3. 所以 *p 和 x 是同一块内存的两种叫法：读 *p 得到 42，写 *p = 100 之后 x 也变 100。反过来 *&x 就是 x——先取地址再解引用，抵消。
  4. 类比：& 是「这个房间门牌号」，p 是「写着门牌号的纸条」，*p 是「照纸条找到房间、进去操作」。纸条本身也是个东西，也有自己的门牌号（&p）。

3.2 & 取地址：只能对左值取

  1. &x、&a[3]、&p 都合法——它们都是内存里真实存在的对象（左值）。
  2. &42、&(a+b) 不合法——表达式结果没有固定地址，编译器不给你取。
  3. 数组的 &a 和 &a[0] 数值相同但类型不同：&a[0] 是 int *，&a 是「指向含 5 个 int 的数组的指针」int (*)[5]。数值一样、步长不一样，D9 细讲数组退化时正面撞上这个。
  4. 每次运行地址都不同（栈位置、ASLR），别去背具体数字，要看的是相对关系：相邻元素差多少、谁大谁小、差值是元素数还是字节数。

3.3 * 解引用：读写的目标由地址 + 类型共同决定

  1. *p = 100; 改的是 p 指向的那块内存。写之前必须保证 p 指向一个真实、可写、类型匹配的对象，否则是未定义行为。
  2. (*p)++ 要带括号：*p++ 会被解析成 *(p++)——先取 *p，再把 p 这根指针往前挪一格，改的不是 x。这是运算符优先级坑，今天先记住写法，traps.c 里也会提示。
  3. 未初始化的指针（如 int *uninit;）里是垃圾值，*uninit 会往随便一个地址写——教学代码里连它的值都不打印，读了就已经不安全。
  4. 空指针 NULL 指向地址 0，*NULL 必崩。用之前先判空是后面 D31/工程阶段的基本纪律。

3.4 指针宽度：本机 8 字节，跟指向什么无关

  1. 指针里装的是地址，宽度 = 本机地址总线位数。64 位机上 sizeof(char*) == sizeof(int*) == sizeof(double*) == 8。本机实测：
    • char=1 short=2 int=4 long=4 double=8 void* =8（Windows x64，LLP64，long 仍是 4）。
  2. 常见误解纠正：char* 不是「1 字节宽的指针」，它是「指向 char 的指针」，指针本身照样 8 字节；窄的是它指向的东西，不是它自己。
  3. 指针宽度决定「地址能覆盖多大空间」：8 字节 = 2^64 个可能地址。long 在 Windows 是 4、在 Linux x86-64 是 8，写跨平台代码别假设 sizeof(long) == sizeof(void*)。
  4. sizeof(指针) 给的是纸条多大，sizeof(*指针) 给的是房间里那个东西多大。这两个别混。

3.5 地址运算：p+1 跳的是「一格」，不是「一字节」

  1. C 定义 p + k 等价于「地址前移 k * sizeof(*p) 字节」。所以 int *p 的 p+1 跳 4 字节，char *cp 的 cp+1 跳 1 字节，double * 跳 8 字节。
  2. 这是编译器自动按类型缩放的，源码里写 +1 就行，不用手写 +4。反过来，把 int* 强转成 char* 再做 +1，就变成逐字节走——ptr.c step 模式用这招把 int 的内部字节掏出来看。
  3. 指针相减 p2 - p1 反过来：结果是「相差几个元素」，不是几个字节。&a[4]-&a[0] == 4，想要字节数就先都转成 char* 再减，得 16。
  4. 只有指向同一数组的两个指针相减才有定义。拿 &y - &x（两个不相干局部变量）相减是未定义行为——编译器可能给出看似合理的数字，但标准不保证，别写。

3.6 one-past：地址能算，不能读

  1. 数组 a[5]，a+5（= &a[5]）是「尾后一位」地址，C 允许你形成和比较它，用来做循环边界（for (p=a; p<a+5; p++)）。
  2. 但 *（a+5） 读的是数组外面，未定义行为。traps.c 演示了这一点但不去真正解引用。
  3. 合法可解引用的下标只有 0..4。这条跟 D5 的越界是同一件事在指针视角的说法。

3.7 最小可运行示例：min.c（无参数，一份文件跑完核心四件事）

#include <stdio.h>

int main(void) {
    int x = 42;
    int a[3] = {10, 20, 30};
    int *p = &x;
    char *cp = (char *)&x;

    printf("sizeof(int)=%zu sizeof(char*)=%zu sizeof(int*)=%zu\n",
           sizeof(int), sizeof(char *), sizeof(int *));
    printf("&x=%p  p=%p  *p=%d  x=%d\n", (void *)&x, (void *)p, *p, x);

    *p = 100;
    printf("after *p=100: x=%d\n", x);

    printf("p   =%p\n", (void *)p);
    printf("p+1 =%p  delta=%ld bytes\n", (void *)(p + 1),
           (long)((char *)(p + 1) - (char *)p));
    printf("cp  =%p\n", (void *)cp);
    printf("cp+1=%p  delta=%ld bytes\n", (void *)(cp + 1),
           (long)((char *)(cp + 1) - (char *)cp));

    printf("&a[0]=%p &a[1]=%p  diff=%ld ints\n",
           (void *)&a[0], (void *)&a[1], (long)(&a[1] - &a[0]));
    return 0;
}
gcc -std=c11 -Wall -Wextra min.c -o min.exe && ./min.exe

期望（地址是运行时的，只看关系）：

  1. sizeof(int)=4 sizeof(char*)=8 sizeof(int*)=8（64 位机）。
  2. &x 和 p 打印出同一个地址，*p=42，x=42。
  3. after *p=100: x=100——一次写入，两个名字都变。
  4. p+1 比 p 大 4 字节；cp+1 比 cp 大 1 字节。同一块内存，两种步长。
  5. &a[1]-&a[0] 得 1（个元素），不是 4。

3.8 完整可运行示例：ptr.c（addr / step / deref / walk 四模式）

#include <stdio.h>
#include <string.h>

#define MAX_N 64

static void usage(const char *prog) {
    printf("usage:\n"
           "  %s addr\n"
           "  %s step\n"
           "  %s deref\n"
           "  %s walk <n> <n ints>\n",
           prog, prog, prog, prog);
}

/* mode: addr - where do variables live, how wide is a pointer */
static void mode_addr(void) {
    char c = 'A';
    short s = 1;
    int i = 2;
    long l = 3;
    double d = 4.0;
    int *pi = &i;

    printf("type        sizeof  address\n");
    printf("char        %zu      %p\n", sizeof(c), (void *)&c);
    printf("short       %zu      %p\n", sizeof(s), (void *)&s);
    printf("int         %zu      %p\n", sizeof(i), (void *)&i);
    printf("long        %zu      %p\n", sizeof(l), (void *)&l);
    printf("double      %zu      %p\n", sizeof(d), (void *)&d);
    printf("int*        %zu      %p (value=&i)\n", sizeof(pi), (void *)pi);
    printf("void*       %zu\n", sizeof(void *));
    printf("&i=%p  pi=%p  same=%s\n", (void *)&i, (void *)pi,
           &i == pi ? "yes" : "no");
}

/* mode: step - pointer +1 jumps sizeof(pointee), not 1 byte */
static void mode_step(void) {
    int a[5] = {10, 20, 30, 40, 50};
    char *pc = (char *)a;
    int *pi = a;

    printf("base a = %p, sizeof(int)=%zu\n", (void *)a, sizeof(int));
    printf("int* arithmetic:\n");
    for (int k = 0; k < 5; k++) {
        printf("  pi+%d = %p  byte_delta=%ld  value=%d\n", k,
               (void *)(pi + k),
               (long)((char *)(pi + k) - (char *)pi), *(pi + k));
    }
    printf("char* arithmetic:\n");
    for (int k = 0; k < 4; k++) {
        printf("  pc+%d = %p  byte_delta=%ld  byte=0x%02X\n", k,
               (void *)(pc + k), (long)((pc + k) - pc),
               (unsigned char)pc[k]);
    }
    printf("pointer subtraction inside one array:\n");
    printf("  &a[4]-&a[0] = %ld elements (NOT bytes)\n",
           (long)(&a[4] - &a[0]));
    printf("  (char*)&a[4]-(char*)&a[0] = %ld bytes\n",
           (long)((char *)&a[4] - (char *)&a[0]));
}

/* mode: deref - * reads/writes the pointed-to object */
static void mode_deref(void) {
    int x = 42;
    int *p = &x;

    printf("x=%d  &x=%p  p=%p  *p=%d\n", x, (void *)&x, (void *)p, *p);
    *p = 100;
    printf("after *p=100: x=%d  *p=%d\n", x, *p);
    (*p)++;
    printf("after (*p)++: x=%d  *p=%d\n", x, *p);
    printf("*&x = %d (equivalent to x)\n", *&x);
}

/* mode: walk - index and pointer walk address the same elements */
static void mode_walk(int n, const int *a) {
    printf("i    &a[i]       a[i]   *(a+i)  equal\n");
    for (int i = 0; i < n; i++) {
        printf("%-4d %-12p %-6d %-7d %s\n", i, (void *)&a[i], a[i],
               *(a + i), a[i] == *(a + i) ? "yes" : "no");
    }
    const int *q = a;
    printf("pointer walk: ");
    for (int i = 0; i < n; i++) {
        printf("%d%s", *q, i + 1 < n ? " " : "");
        q++;
    }
    printf("\n");
    printf("a+0=%p  a+%d=%p  one-past is legal to FORM\n",
           (void *)a, n, (void *)(a + n));
}

int main(int argc, char **argv) {
    if (argc < 2) {
        usage(argv[0]);
        return 2;
    }
    if (strcmp(argv[1], "addr") == 0) {
        mode_addr();
    } else if (strcmp(argv[1], "step") == 0) {
        mode_step();
    } else if (strcmp(argv[1], "deref") == 0) {
        mode_deref();
    } else if (strcmp(argv[1], "walk") == 0) {
        int n;
        if (argc < 3 || sscanf(argv[2], "%d", &n) != 1 || n < 0 || n > MAX_N) {
            printf("need n in 0..%d\n", MAX_N);
            return 2;
        }
        if (argc - 3 != n) {
            printf("expected %d integers, got %d\n", n, argc - 3);
            return 2;
        }
        int a[MAX_N];
        for (int i = 0; i < n; i++) {
            if (sscanf(argv[3 + i], "%d", &a[i]) != 1) {
                printf("arg %d is not an int\n", i + 1);
                return 2;
            }
        }
        mode_walk(n, a);
    } else {
        printf("unknown mode: %s\n", argv[1]);
        usage(argv[0]);
        return 2;
    }
    return 0;
}

sscanf + 边界检查是 D3/D5 那套输入校验的延续，n 夹在 0..64，数组不开到天上去。

3.9 陷阱演示：traps.c（讲清边界，不真的去崩）

#include <stdio.h>

int main(void) {
    int a[3] = {10, 20, 30};
    int x = 5;
    int y = 9;
    int *uninit; /* declared, never assigned - DO NOT dereference */
    int *nullp = NULL;
    int *one_past = a + 3; /* legal to FORM, illegal to READ */

    printf("1. pointer width is fixed, regardless of pointee type:\n");
    printf("   sizeof(int*)=%zu sizeof(double*)=%zu sizeof(char*)=%zu\n",
           sizeof(int *), sizeof(double *), sizeof(char *));

    printf("2. &x=%p &y=%p ; (&y - &x) is UNDEFINED (different objects)\n",
           (void *)&x, (void *)&y);
    printf("   only subtract pointers into the SAME array: &a[2]-&a[0]=%ld\n",
           (long)(&a[2] - &a[0]));

    printf("3. one-past pointer a+3=%p is a legal address to compute,\n",
           (void *)one_past);
    printf("   but *(a+3) reads past the array -> undefined behavior\n");

    printf("4. null pointer=%p ; dereferencing it crashes (not done here)\n",
           (void *)nullp);

    printf("5. uninitialized pointer holds garbage; *uninit would crash.\n");
    printf("   (value not even printed here - reading it is already unsafe)\n");
    (void)uninit;

    printf("6. int* (+1) jumps %zu bytes; char* (+1) jumps %zu byte\n",
           sizeof(int), sizeof(char));
    return 0;
}

第 2 节：&y - &x 在栈上可能看着像 1 或 -1，但两个不相干对象相减是 UB，标准不保证，别拿它当规律。第 5 节连未初始化指针的值都不打印——读它本身就已经不安全了。

本机没有 C 编译器，三份代码已过 C11 语法解析（pycparser）。你在自己机器上按第 4 节命令实编译、实运行，地址以实跑为准；步长、宽度、差值是确定的，可拿讲义数字逐条对。

4.2 课表硬条件一：解释 int* 加 1 为什么跳 4 字节

  1. 不看资料写出 C 的规则：p + k 前移 k * sizeof(*p) 字节。int 占 4 字节，所以 int* 的 +1 跳 4；char* 跳 1；double* 跳 8。
  2. 用 step 模式把 pi+0..4 的 byte_delta 抄进笔记：0 4 8 12 16，说明这不是「地址加 1」，是「往后挪一个 int」。
  3. 改一行代码验证：把 int *pi = a; 换成 double *，+1 的步长立刻变 8（或另写一个 double d[2]; double *pd=d; 打印）。写一句话结论：步长由指针类型决定，不由地址数值决定。

4.3 课表硬条件二：说出本机指针宽度

  1. addr 模式读出 sizeof(int*) = sizeof(char*) = sizeof(double*) = sizeof(void*) = 8（64 位机），写进笔记：本机指针宽度 = 8 字节 = 64 位。
  2. 回答这个判断题并写理由：char* 比 int* 窄吗？——不窄，都是 8 字节；窄的是它指向的 char（1 字节），不是指针自己。
  3. 用 sizeof(指针) 和 sizeof(*指针) 各举一例：sizeof(pi)=8（纸条），sizeof(*pi)=4（房间里那个 int）。两个数含义不同，别写反。

4.4 手动 ±1，做自己的地址记录表

对 int a[5]={10,20,30,40,50}，先跑 step 拿到真实地址，再在 note.md 里手填下表（地址抄程序输出，差值自己算）：

表达式 地址(抄输出) 相对 a 的字节偏移 说明
a / &a[0] 0 首元素
a+1 / &a[1] 4 下一个 int
a+4 / &a[4] 16 最后一个元素
a+5 20 one-past，能算不能读
&a[4]-&a[0] — 4 个元素 = 16 字节 同数组相减合法

写一句自查：a+5 这个地址打印出来了，但如果写 *(a+5) 会怎样？（答：未定义行为，可能读到别的变量、可能崩、也可能看着正常。）
