2. 学术雷达 · 第 2 期（2026-11-11 检索）

今天两条都撞在同一个点上：一个数字占几位、这几个位怎么摆，直接决定机器能跑多快。跟今天的课是正面相关，不是硬凑。

2.1 FOSCAR：把 2-bit / 4-bit KV Cache 真正跑快

  • 出处：arXiv:2611.09722《FOSCAR: Accelerating Decode Attention over 2- and 4-Bit KV Caches through Affine Folding》，v1 2026-11-06，cs.AI；机构 Together AI、University of Sydney；代码 https://github.com/FutureMLS-Lab/FOSCAR 。
  • 做了什么：LLM 每吐一个 token 都要把 KV cache 从显存读一遍，压成 INT2/INT4 能省带宽，但作者测出现有 2-bit 融合核在 H100/B200 上只跑到峰值 HBM 吞吐的 31% / 15%——卡在「每个值都要乘 scale、加 offset、再喂 Tensor Core」，指令发射吞吐不够。做法是把 scale/offset 折到矩阵乘的另一个操作数或输出上（affine folding），反量化结果在精确算术下等价；再用位操作把 INT2 直接打包喂 Tensor Core，H100 / B200 上每个 INT2 元素只要 1 / 0.19 条 ALU 指令。H100 上 INT2 核比 FlashInfer BF16 几何平均快 3.36×，长上下文服务峰值吞吐相对 2-bit 基线最高 +170%。
  • 改变了哪个旧假设：「位宽压下去，延迟就自动降」。实际收益被逐元素解包的指令开销吃光了；而且旧做法默认缩放必须逐元素还原，这篇证明它可以挪到乘法的另一侧。
  • 意义：低比特量化从「省显存」变成「真省时间」，位级布局（怎么移位、怎么掩码、几个 bit 塞进一个寄存器）成了性能主战场。
  • 关联今天：INT2/INT4 就是「占几位、这几位怎么解释」；<<、&、掩码、无符号回绕正是他们打包用的操作；「精确算术下等价」就是今天要练的「位模式不变，换个类型解释」。你今天写 print_bits 看 -1 是全 1，和论文里把量化整数按位塞进 Tensor Core 是同一套动作。
  • 状态：arXiv 预印本，未经同行评审、待复现；加速数字是作者在 H100/B200 + SGLang 上的自测，库已开源但尚无独立复现。

2.2 Tri-Stack-PIM：三层异构晶粒把带宽墙拆开

  • 出处：arXiv:2611.13644《Tri-Stack-PIM: A Heterogeneous Multi-Die 3D-Integrated Processing-in-Memory Architecture for Efficient LLM Inference》，v1 2026-11-10，cs.AR；机构 北京邮电大学、复旦大学；11 页 9 图。
  • 做了什么：LLM 自回归 decode 本质是内存带宽受限。已有 3D 堆叠存内计算把 PHY/DMA/控制器和运算单元挤在同一片先进制程 base die，且用 DRAM 工艺做计算单元逻辑密度上不去。这篇改成三层：顶层 DRAM 只管存，中层成熟制程放接口、控制、近存计算，底层先进制程专放 SIMD MAC 阵列；再加跨 die 乱序微操作调度器 UBAR，把顺序执行会白丢的周期找回最多 90%。相对 GPU 基线几何平均加速 4.95×，能量延迟积相对朴素参数选择降 33–66×。
  • 改变了哪个旧假设：「存内计算的控制逻辑和算力必须放同一片 die、同一工艺」「跨 die 依赖只能靠顺序执行保正确性」。
  • 意义：接口扩展和算力供给可以解耦，带宽墙能从封装/工艺分层绕过去。
  • 关联今天：decode 为什么受带宽限制？每生成一个 token 都要搬一遍权重和 KV，搬多少字节 = 单个数的字节数 × 数量。今天 sizeof 打出来的那张表，乘上参数量就是这堵墙。2.1 从「把数压小」下手，2.2 从「把搬运距离压短」下手，是同一瓶颈的两条解法。
  • 状态：arXiv 预印本，未经同行评审、待复现；数字来自架构仿真，没有流片实测。

今日雷达一句话：位宽不是抽象概念，是带宽、指令数、功耗的具体数字。今天把 sizeof 和补码搞明白，后面 int8 量化、KV cache、推理优化才有地方挂。

3. 新知讲解

3.1 类型只决定三件事

  1. 占几字节 → sizeof。
  2. 这几个位怎么解释 → 整数用补码，浮点用 IEEE 754。
  3. 能参与什么运算 → %、<<、& 只给整数；/ 对整数和浮点是两套语义。

变量就是「有名字、有大小、有地址的一块内存」，类型是贴在这块内存上的说明书。D1 讲的「大小/地址」今天补上「怎么解释」。

3.2 整型大小：标准没写死，ABI 说了算

  1. 标准只规定最小范围（char ≥ 8 位、short ≥ 16、int ≥ 16、long ≥ 32、long long ≥ 64）和 sizeof(char) <= sizeof(short) <= sizeof(int) <= sizeof(long) <= sizeof(long long)，不规定具体字节数。
  2. 64 位 Windows 是 LLP64：int 4、long 4、指针 8；64 位 Linux 是 LP64：int 4、long 8、指针 8。所以 D1 的答案是「我实测的」，不是背的。
  3. char 保证恰好 1 字节，但 1 字节不一定 8 位，看 <limits.h> 的 CHAR_BIT（现代主流都是 8）。char 带不带符号由实现决定，要明确的符号就写 signed char / unsigned char。
  4. float 通常 4 字节（binary32）、double 8 字节（binary64），0.1 存不精确，禁止用 == 比较浮点。
  5. sizeof 返回 size_t，打印用 %zu，别用 %d。

3.3 补码：为什么 -1 是全 1

  1. N 位补码范围 -2^(N-1) ~ 2^(N-1)-1，0 只有一种表示（原码/反码有 ±0），符号位直接参与加法，加减能用同一套电路——这才是全行业选它的原因。
  2. 取负数 = 按位取反 +1。8 位为例：5 = 00000101 → 取反 11111010 → 加 1 = 11111011 就是 -5；5 + (-5) = 1 00000000，最高位进位丢掉，得 0。
  3. -1 同理：00000001 → 11111110 → 11111111。所以 (unsigned int)-1 打出来是 UINT_MAX（32 位下 4294967295），位没变，只是换了解释方式。
  4. C11 允许非补码实现，C23 起补码写进标准；你手上的 x86/ARM 都是补码。

3.4 位运算：只对 unsigned 用

  1. & 取位 / 清位、| 置位、^ 翻转、~ 取反、<< >> 移位。
  2. 三行模板：置位 f |= 1u << k;、清位 f &= ~(1u << k);、判奇偶 (n & 1u) != 0u。
  3. 有符号数右移是实现定义（算术还是逻辑）、左移溢出是 UB，做位操作一律先转 unsigned。
  4. 位运算优先级低于比较运算，必须加括号：if ((f & 1u) == 0u)，写成 f & 1u == 0u 会被解析成 f & (1u == 0u)。

3.5 溢出：一半标准保证，一半是 UB

  1. unsigned 溢出按 2^N 回绕，标准保证，可以拿来写环形缓冲、哈希。
  2. 有符号溢出是未定义行为（UB），不是「变成负数」。编译器会假定它不发生，-O2 下连你写的 if (a + 1 < a) 都可能被整个优化掉。
  3. 想亲眼看回绕：用 unsigned，或者用 gcc/clang 的 -fwrapv（编译器扩展，不是标准 C，别写进结论）。
  4. 正确防御是先判断再算：if (a > INT_MAX - b) { /* 拒绝 */ } else { sum = a + b; }。
  5. 这就是后面 int8 量化的坑：权重压到 8 位后累加器一溢出，结果直接废掉。今天先把「位宽 × 范围」刻进脑子。

3.6 运算符里最容易翻车的四处

  1. 整数除法向零截断：5 / 2 == 2，5.0 / 2 == 2.5；-5 % 2 == -1，余数符号跟被除数。
  2. ++i 先加后用、i++ 先用后加；同一表达式里对同一变量改两次是 UB，别写 i = i++ + 1。
  3. 隐式转换：有符号和无符号混算，有符号被转成无符号。所以 -1 < 1u 是假——-1 先变成 UINT_MAX。混用类型前先想清楚。
  4. char/short 参与运算会先提升成 int；sizeof 是编译期运算符，不是函数。

3.7 最小可运行示例：types.c

#include <stdio.h>
#include <limits.h>
#include <string.h>

static void print_bits(unsigned int v, int n) {
    for (int i = n - 1; i >= 0; i--) {
        putchar(((v >> i) & 1u) ? '1' : '0');
        if (i > 0 && i % 8 == 0) putchar(' ');
    }
}

int main(void) {
    printf("== sizeof (bytes) ==\n");
    printf("char      %zu\n", sizeof(char));
    printf("short     %zu\n", sizeof(short));
    printf("int       %zu\n", sizeof(int));
    printf("long      %zu\n", sizeof(long));
    printf("long long %zu\n", sizeof(long long));
    printf("float     %zu\n", sizeof(float));
    printf("double    %zu\n", sizeof(double));
    printf("size_t    %zu\n", sizeof(size_t));
    printf("void*     %zu\n", sizeof(void *));

    printf("\n== limits ==\n");
    printf("int       %d .. %d\n", INT_MIN, INT_MAX);
    printf("unsigned  0 .. %u\n", UINT_MAX);
    printf("long long %lld .. %lld\n", LLONG_MIN, LLONG_MAX);

    printf("\n== two's complement ==\n");
    int neg_one = -1;
    printf("-1 as unsigned : %u\n", (unsigned int)neg_one);
    printf("-1 low 8 bits  : ");
    print_bits((unsigned int)neg_one & 0xffu, 8);
    putchar('\n');
    unsigned int x = 5u;
    unsigned int neg5 = (~x + 1u) & 0xffu;
    printf(" 5 bits        : ");
    print_bits(x, 8);
    putchar('\n');
    printf("-5 bits        : ");
    print_bits(neg5, 8);
    putchar('\n');
    printf("5 + (-5) bits  : ");
    print_bits((x + neg5) & 0xffu, 8);
    putchar('\n');

    printf("\n== bit ops ==\n");
    unsigned int flags = 0u;
    flags |= 1u << 3;
    printf("set bit3 : 0x%02x\n", flags);
    flags &= ~(1u << 3);
    printf("clr bit3 : 0x%02x\n", flags);
    flags ^= 1u << 2;
    printf("tgl bit2 : 0x%02x\n", flags);
    printf("7&3=%u 7|8=%u 7^3=%u\n", 7u & 3u, 7u | 8u, 7u ^ 3u);

    printf("\n== unsigned wrap (standard-defined) ==\n");
    unsigned char u255 = 255u;
    printf("255u + 1 = %u\n", (unsigned int)(unsigned char)(u255 + 1u));
    printf("0u   - 1 = %u\n", (unsigned int)(unsigned char)(0u - 1u));

    printf("\n== same bits, different type ==\n");
    unsigned int next_bits = (unsigned int)INT_MAX + 1u;
    int as_int = 0;
    memcpy(&as_int, &next_bits, sizeof as_int);
    printf("0x%08x read as int = %d\n", next_bits, as_int);

    printf("\n== overflow check before computing ==\n");
    int big = INT_MAX;
    if (big > INT_MAX - 100) {
        printf("INT_MAX + 100 rejected\n");
    } else {
        printf("%d\n", big + 100);
    }
    int s = -1;
    unsigned int u = 1u;
    printf("-1 < 1u : %s\n", (s < u) ? "true" : "false");

    return 0;
}

-Wall -Wextra 下最后那个比较会报 -Wsign-compare，故意留着：请把这条警告抄进笔记，它就是 3.6 第 3 条的实物证据。

4.2 单位换算器 convert.c（课表要求的产出）

#include <stdio.h>
#include <stdlib.h>

static void die(const char *msg) {
    fprintf(stderr, "%s\n", msg);
    exit(EXIT_FAILURE);
}

int main(void) {
    static const double to_meter[5] = {0.0, 1000.0, 1.0, 0.01, 0.001};
    int from = 0;
    int to = 0;
    double v = 0.0;

    printf("units: 1=km 2=m 3=cm 4=mm\n");
    printf("from: ");
    if (scanf("%d", &from) != 1) die("bad from");
    printf("value: ");
    if (scanf("%lf", &v) != 1) die("bad value");
    printf("to: ");
    if (scanf("%d", &to) != 1) die("bad to");
    if (from < 1 || from > 4 || to < 1 || to > 4) die("unit out of range");

    double k = to_meter[from] / to_meter[to];
    printf("%.6g * %.6g = %.6g\n", v, k, v * k);
    printf("5/2=%d 5.0/2=%.1f -5%%2=%d\n", 5 / 2, 5.0 / 2, -5 % 2);
    return 0;
}
gcc -std=c11 -Wall -Wextra convert.c -o convert.exe
printf "1\n1\n2\n" | ./convert.exe
printf "2\n2.5\n3\n" | ./convert.exe
printf "4\n500\n2\n" | ./convert.exe

三条期望：1000、250、0.5。再喂 0、负数、1e308 各一次，程序不能崩；1e308 换算到 mm 会打成 inf（超出 double 范围），这是预期行为，记一笔别当 bug。这三条的输出窗口截图存盘（课表点名要截图）。

4.3 用位运算亲眼看有符号溢出

#include <stdio.h>
#include <limits.h>

int main(void) {
    int x = INT_MAX;
    int y = x + 1;
    printf("INT_MAX = %d\n", x);
    printf("INT_MAX + 1 = %d\n", y);
    printf("y < 0 : %s\n", y < 0 ? "yes" : "no");
    return 0;
}
gcc -std=c11 -Wall -Wextra -fwrapv -O0 wrap.c -o wrap.exe && ./wrap.exe

4.4 加一个位计数（改在 types.c 里）

static int popcount8(unsigned int v) {
    int n = 0;
    while (v) {
        n += (int)(v & 1u);
        v >>= 1;
    }
    return n;
}

调用 printf("popcount = %d\n", popcount8((unsigned int)-1 & 0xffu));，应输出 8。再用 popcount8(0x5au) 对一下手算结果。
