3.1 RootSink：崩溃那一行，往往不是错的那一行

  1. 出处：arXiv:2611.23336，v1 2026-11-17，cs.SE；Suryansh Singh Sijwali、Achintya Lakshmanan、Abhiram Dodda、Shaiful Chowdhury、Suman Saha。abs 页未逐作者印机构，不臆断。预印本，未经同行评审、待复现。
  2. 做了什么：从 354 个开源项目整理 3341 条 C/C++ 崩溃记录，每条给出「内存错误检测器报的崩溃点（sink）」+「候选根因点（root）」+ 弱点类型及证据；其中 1954 条属 Reproduced 层（自己复跑确认、修复版跑干净），1275 条用开发者的单个 hunk 就能止崩，标为 tested repair site。盲审里两位作者给 tested repair site 打「就是缺陷」的比例是 68%/92%，但给定位到的根因打这个分的只有 37%/51%。
  3. 改变了哪个旧假设：推翻「ASan/崩溃报告指的那一行 = 出错的那一行」。崩溃点是症状（sink），根因常在别处；能止崩的补丁位置也不一定是缺陷位置。
  4. 意义：给自动修复、漏洞定位模型提供第一批带「根因 vs 崩溃点」双标注和证据的数据，评估终于能对准根因而非止崩。
  5. 关联今天：你的 mini_vector 用 realloc 扩容，最典型的坑就是——ASan 报 heap-use-after-free 的位置（读旧指针那行）和真正根因（扩容时没把新指针赋回、或调用方还留着旧地址）隔了好几行。今天写的时候故意想清楚「哪一行会崩、哪一行才是错」。

3.2 Taint Analysis via Heap-Aware Propagation：柔性数组让整个结构体失去精度

  1. 出处：arXiv:2611.20453，v1 2026-11-16，cs.LO / cs.CR / cs.PL；Yusen Su 等（abs 页列 3 作者）；VMCAI 2027 论文扩展版。预印本，未经同行评审、待复现。
  2. 做了什么：指出 DSA 风格指针分析在一个常见模式上掉精度——C 结构体同时含标量字段和柔性数组成员（int data[]），一旦用符号下标访问柔性数组，DSA 会把整个对象所有字段的 points-to 信息糊在一起，污点分析随之误报爆炸。提出 I-DSA，用「区间」表示字段位置，符号边界的指针只合并区间内的字段，其余字段保持精确；基于 SeaDSA + Crab 实现，针对 LLVM IR。
  3. 改变了哪个旧假设：推翻「用符号下标碰了柔性数组，整个 struct 就必然失去字段敏感度」。改成区间建模后，非目标字段仍能精确跟踪。
  4. 意义：对含柔性数组/动态缓冲区的堆结构，污点与别名分析误报显著下降，且指针分析开销增加很小。
  5. 关联今天：柔性数组 struct { size_t n; int data[]; } 就是动态数组的另一种 C 写法。你写的 Vec { int *data; size_t size; size_t cap; } 是「指针外挂堆块」版——分析器必须把结构体字段和它指向的堆块分开跟踪，否则一次 data[i] 写入会把 size/cap 也污染掉。这条论文守的正是「堆对象与容器元数据要分开建模」这件事。

4. 新知讲解：动态数组

4.1 一句话定义

  1. 动态数组 = 三段状态：data（指向一块连续堆内存）、size（当前存了几个）、cap（这块内存能装几个）。不变式恒为 0 <= size <= cap。
  2. 它同时给了你两样静态数组没有的东西：运行时决定长度、 amortized O(1) 尾部追加。代价是手动 free。

4.2 为什么必须扩容，且必须翻倍

  1. malloc/realloc 分配的内存不能“原地往后长”。cap 满了要追加，只能申请一块更大的、把旧数据拷过去、释放旧块——这就是 realloc 帮你做的事。
  2. 扩容策略是 cap = cap ? cap*2 : 4（首次给 4）。翻倍的关键：从空开始 push n 次，扩容次数是 log₂n，总拷贝量 < 2n，摊到每次 push 是 O(1)。若改成 cap+1，每 n 次就整体拷一次，总量 O(n²)，10000 次会明显卡。
  3. 手算本例扩容序列：cap 0→4（第1次push）→8（第5次push）→16（第9次push）…。10000 次 push 后 cap = 16384（2¹⁴，大于 10000 的最小 2 的幂）。

4.3 realloc 三条陷阱

  1. 不能先覆盖旧指针：p = realloc(v->data, nc) 失败返回 NULL 时，旧块没被释放、v->data 仍有效。直接写 v->data = realloc(...) 一旦失败就把唯一指针丢了，内存泄漏 + 无法恢复。必须先接临时 p，判空，再赋回。
  2. 旧指针全部失效：realloc 可能搬走整块内存。扩容前保存的 int *q = v->data 或 &v->data[i]，扩容后全部悬空。今天检验里“扩容为什么要 realloc、旧指针为什么失效”就是这条。
  3. 溢出保护：nc * sizeof(int) 可能溢出 size_t，导致申请到比预期小的块、随后越界写。加 if (nc > SIZE_MAX / sizeof(int)) return -1。

4.4 pop / reserve / 边界

  1. pop 只做一件事：size--，把最后一个元素作为返回值给调用方。它不 free、不缩容——那块槽位还在 data[size] 里，但已不在逻辑范围内（这正是 2.1 RootSink 里“止崩点不等于根因”的温床：重复 pop 读到 stale 值不会崩，但逻辑错了）。
  2. reserve(n) 只增不减：目标 cap 大于当前才动。预分配能消除中途多次扩容。本例 reserve(8) 时 cap 已是 64，保持不变。
  3. 空上 pop 返回 -1、不访问内存；get(i) 先判 i < size 再访问。整数极值 INT_MAX/INT_MIN/0/-7 原样往返，证明存储层不篡改值。

4.5 ASan 怎么验

  1. 编译：gcc -std=c11 -Wall -Wextra -g -fsanitize=address mini_vector.c -o mini_vector && ./mini_vector
  2. -g 让报告带源码行号；-fsanitize=address 同时开越界检测与泄露检测（LeakSanitizer）。
  3. 三类报告要对得上：heap-buffer-overflow（越界写，如 cap 算错）、heap-use-after-free（用了扩容前的旧指针）、detected memory leaks（某个路径少 free）。零报错才算过。

4.6 最小可运行示例（已落盘 project/min.c，9 行输出逐字可复现）

/* min.c - D13 minimal dynamic array: init / push / grow / pop / free.
 * Build: gcc -std=c11 -Wall -Wextra -g -fsanitize=address min.c -o min && ./min
 */
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>

typedef struct { int *data; size_t size; size_t cap; } Vec;

static void die(const char *m){ fprintf(stderr, "%s\n", m); exit(1); }
void vec_init(Vec *v){ v->data = NULL; v->size = 0; v->cap = 0; }

int vec_reserve(Vec *v, size_t nc){
    if (nc <= v->cap) return 0;
    if (nc > SIZE_MAX / sizeof(int)) return -1;
    int *p = (int*)realloc(v->data, nc * sizeof(int));
    if (!p) return -1;
    v->data = p; v->cap = nc; return 0;
}

int vec_push(Vec *v, int x){
    if (v->size == v->cap){
        size_t nc = v->cap ? v->cap * 2 : 4;
        if (vec_reserve(v, nc)) return -1;
    }
    v->data[v->size++] = x; return 0;
}

int vec_pop(Vec *v, int *out){
    if (v->size == 0) return -1;
    v->size--;
    if (out) *out = v->data[v->size];
    return 0;
}

int vec_get(const Vec *v, size_t i, int *out){
    if (i >= v->size) return -1;
    *out = v->data[i]; return 0;
}

void vec_free(Vec *v){ free(v->data); v->data = NULL; v->size = 0; v->cap = 0; }

static void dump(const char *tag, const Vec *v){
    printf("%-9s size=%zu cap=%zu data=[", tag, v->size, v->cap);
    for (size_t i = 0; i < v->size; i++){ if (i) printf(","); printf("%d", v->data[i]); }
    printf("]\n");
}

int main(void){
    Vec v; vec_init(&v);
    const char *tags[5] = {"push1","push2","push3","push4","push5"};
    dump("init", &v);
    for (int i = 1; i <= 5; i++){
        if (vec_push(&v, i * 10)) die("push failed");
        dump(tags[i - 1], &v);
    }
    int out = 0;
    if (vec_pop(&v, &out)) die("pop failed");
    printf("pop  -> %d\n", out); dump("afterpop", &v);
    vec_free(&v); dump("freed", &v);
    return 0;
}

push5     size=5 cap=8 data=[10,20,30,40,50]
